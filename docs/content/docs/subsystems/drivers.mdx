Drivers are the low-level transport layer in Herald. Each driver knows how to deliver a message through a specific external service. Herald ships with six built-in drivers covering all four channels, and the `Driver` interface allows you to add custom drivers.

## Driver Interface

Every driver implements the `driver.Driver` interface:

```go
type Driver interface {
    // Name returns the driver identifier (e.g., "smtp", "twilio", "fcm").
    Name() string

    // Channel returns which notification channel this driver handles.
    Channel() string

    // Send delivers a message and returns a delivery result.
    Send(ctx context.Context, msg *OutboundMessage) (*DeliveryResult, error)

    // Validate checks if the provided credentials and settings are valid.
    Validate(credentials, settings map[string]string) error
}
```

## OutboundMessage

The `OutboundMessage` is the normalized message format passed from Herald to every driver:

```go
type OutboundMessage struct {
    To       string            `json:"to"`
    From     string            `json:"from,omitempty"`
    FromName string            `json:"from_name,omitempty"`
    Subject  string            `json:"subject,omitempty"`
    HTML     string            `json:"html,omitempty"`
    Text     string            `json:"text,omitempty"`
    Title    string            `json:"title,omitempty"`
    Data     map[string]string `json:"data,omitempty"`

    // Push holds per-message push options. Nil means the v1.8 behaviour.
    Push *PushOptions `json:"-"`
    // PublicKey is the recipient device's X25519 public key. Push fan-out only.
    PublicKey []byte `json:"-"`
}
```

The `Data` map contains the provider's credentials and settings, injected by Herald during delivery. Drivers read their configuration values from this map.

## DeliveryResult

Drivers return a `DeliveryResult` on success:

```go
type DeliveryResult struct {
    ProviderMessageID string         `json:"provider_message_id,omitempty"`
    Status            message.Status `json:"status"`
}
```

The `ProviderMessageID` is the external identifier assigned by the service (e.g., Resend email ID, Twilio SID, FCM message name).

## Driver Registry

Drivers are registered in a thread-safe `Registry` and looked up by name at send time:

```go
registry := driver.NewRegistry()
registry.Register(&email.SMTPDriver{})
registry.Register(&email.ResendDriver{})
registry.Register(&sms.TwilioDriver{})
registry.Register(&push.FCMDriver{})
registry.Register(&inapp.Driver{})

// Lookup at send time
drv, err := registry.Get("smtp")
```

The registry also supports listing drivers by channel:

```go
emailDrivers := registry.ListByChannel("email")
// Returns: [SMTPDriver, ResendDriver]
```

When using Herald through the Forge extension, all built-in drivers are registered automatically.

## Built-in Drivers

Each table lists the keys a driver reads and where each one goes. A credential goes in the provider's `credentials`, which Herald encrypts at rest once you set a key, and a secret always belongs there. A setting goes in `settings` and stays readable. Herald refuses a provider that puts a setting in `credentials`, and it refuses `base_url` and `host` there for every driver. The tables follow each driver's `Fields()` method, which is where the placement comes from.

### SMTP

The SMTP driver delivers email via standard SMTP protocol with optional TLS.

| Key | Goes in | Required | Secret | Description |
|-----|---------|----------|--------|-------------|
| `host` | Setting | Yes | No | SMTP server hostname |
| `port` | Setting | Yes | No | SMTP server port (usually 25, 465, or 587) |
| `use_tls` | Setting | No | No | Set to `"true"` for direct TLS connection |
| `username` | Credential | No | No | SMTP authentication username |
| `password` | Credential | No | Yes | SMTP authentication password |
| `from` | Setting | No | No | From address, used when no routing rule sets one |
| `from_name` | Setting | No | No | From display name |

```go
driver := &email.SMTPDriver{}
driver.Name()    // "smtp"
driver.Channel() // "email"
```

**How it works**: The driver constructs an RFC 2822 message with `From`, `To`, `Subject`, and `Content-Type` headers. If `username` is provided, it authenticates using `smtp.PlainAuth`. When `use_tls` is `"true"`, the driver opens a direct TLS connection (implicit TLS on port 465); otherwise, it uses `smtp.SendMail` which supports STARTTLS.

HTML content takes priority over plain text when both are present in the outbound message:

```go
content := msg.Text
contentType := "text/plain"
if msg.HTML != "" {
    content = msg.HTML
    contentType = "text/html"
}
```

### Resend

The Resend driver delivers email via the [Resend](https://resend.com) HTTP API.

| Key | Goes in | Required | Secret | Description |
|-----|---------|----------|--------|-------------|
| `api_key` | Credential | Yes | Yes | Resend API key |
| `base_url` | Setting | No | No | API base URL (defaults to `https://api.resend.com`) |
| `from` | Setting | No | No | From address, used when no routing rule sets one |
| `from_name` | Setting | No | No | From display name |

```go
driver := &email.ResendDriver{}
driver.Name()    // "resend"
driver.Channel() // "email"
```

**How it works**: The driver sends a JSON POST request to `{base_url}/emails` with the `Authorization: Bearer {api_key}` header. Both HTML and plain text bodies are included when available. The response contains the Resend message ID, which is returned as `ProviderMessageID`.

```go
// Request body sent to Resend API
type resendRequest struct {
    From    string   `json:"from"`
    To      []string `json:"to"`
    Subject string   `json:"subject"`
    HTML    string   `json:"html,omitempty"`
    Text    string   `json:"text,omitempty"`
}
```

### Twilio

The Twilio driver delivers SMS via the [Twilio](https://www.twilio.com) REST API.

| Key | Goes in | Required | Secret | Description |
|-----|---------|----------|--------|-------------|
| `account_sid` | Credential | Yes | No | Twilio Account SID |
| `auth_token` | Credential | Yes | Yes | Twilio Auth Token |
| `from_number` | Setting | Yes | No | Sender phone number (E.164 format) |
| `base_url` | Setting | No | No | API base URL (empty means Twilio's own API) |

```go
driver := &sms.TwilioDriver{}
driver.Name()    // "twilio"
driver.Channel() // "sms"
```

**How it works**: The driver sends a form-encoded POST to Twilio's Messages API endpoint (`/2010-04-01/Accounts/{AccountSID}/Messages.json`). Authentication uses HTTP Basic Auth with the Account SID and Auth Token. The `From` number can be overridden by [scoped config](/docs/subsystems/scoped-config). The response SID is returned as `ProviderMessageID`.

```go
data := url.Values{}
data.Set("To", msg.To)
data.Set("From", fromNumber)
data.Set("Body", msg.Text)
```

### FCM (Firebase Cloud Messaging)

The FCM driver delivers push notifications via the [Firebase Cloud Messaging](https://firebase.google.com/docs/cloud-messaging) HTTP v1 API.

| Key | Goes in | Required | Secret | Description |
|-----|---------|----------|--------|-------------|
| `project_id` | Setting | Conditional | No | Firebase project ID. Optional with a `service_account`, which carries its own |
| `service_account` | Credential | Conditional | Yes | The service account JSON key. Herald mints and refreshes access tokens from it |
| `access_token` | Credential | Conditional | Yes | OAuth2 access token. It's short-lived and Herald doesn't refresh it |
| `server_key` | Credential | Conditional | Yes | Legacy server key (fallback) |
| `base_url` | Setting | No | No | API base URL (empty means Google's own API) |

Set one of `service_account`, `access_token` or `server_key`. If you set more than one, `service_account` wins, then `access_token`, then `server_key`.

```go
driver := &push.FCMDriver{}
driver.Name()    // "fcm"
driver.Channel() // "push"
```

**How it works**: The driver sends a JSON POST to `https://fcm.googleapis.com/v1/projects/{projectID}/messages:send`. The `msg.To` field is the FCM device token. The message carries a notification (title and body) and the `data.` settings as data.

With a `service_account`, the driver signs a JWT, exchanges it for an access token and caches the token per key. It replaces a cached token five minutes before it expires, so you share one `FCMDriver` instead of making one per send. When `project_id` is empty it reads the key's own `project_id`. A failed mint reports the status code and nothing else, never the key or the client email.

**Push options**: `DataOnly` drops the notification block and sends data alone. `Push.Data` merges into the data and wins over a `data.` setting. When there are options, the driver sets an `android` block: `collapse_key` from `CollapseID`, a `ttl` in whole seconds, and a priority that is `HIGH` for `time_sensitive` and `critical` and `NORMAL` otherwise.

**Dead tokens**: An `UNREGISTERED` error, or a bad `message.token` field, comes back as `driver.ErrAddressGone`. A bad field anywhere else in the message is a bug in your payload and stays an ordinary error.

### APNs

The APNs driver delivers push to iOS through Apple's HTTP/2 API. It lives in its own module, `github.com/xraph/herald/drivers/apns`, and needs Herald v1.9.0.

| Key | Goes in | Required | Secret | Description |
|-----|---------|----------|--------|-------------|
| `key_id` | Setting | Yes | No | The key ID of your `.p8` key |
| `team_id` | Setting | Yes | No | Your Apple team ID |
| `bundle_id` | Setting | Yes | No | Sent as the `apns-topic` header |
| `private_key` | Credential | Yes | Yes | The PKCS#8 PEM from Apple |
| `sandbox` | Setting | No | No | `"true"` to use Apple's development servers |
| `base_url` | Setting | No | No | API base URL, for tests |

```go
h, err := herald.New(
    herald.WithStore(myStore),
    herald.WithDriver(&apns.Driver{}),
)
```

**Payload**: Herald builds the `aps` dictionary from the message and the push options. The title and body become the alert, with the default sound. Then each option adds its own key:

| Option | APNs |
|--------|------|
| `Urgency` | `interruption-level` (`passive`, `active`, `time-sensitive`, `critical`) and the `apns-priority` header: 5 for `passive`, 10 otherwise |
| `critical` urgency | The sound becomes a critical sound dictionary |
| `MutableContent` | `mutable-content: 1` |
| `ContentAvailable` | `content-available: 1` |
| `Category`, `ThreadID` | `category`, `thread-id` |
| `Data` | Custom top-level keys. A key named `aps` is ignored |
| `TTL` | The `apns-expiration` header, as a Unix time |
| `CollapseID` | The `apns-collapse-id` header |

A background push has no title and no text and sets `ContentAvailable`. It goes out with the push type `background`, priority 5, and an `aps` that holds `content-available` and nothing else, which is what Apple requires. A push with nothing to show that isn't a background push returns an error and sends nothing.

**Dead tokens**: A 410, or a 400 with the reason `BadDeviceToken`, comes back as `driver.ErrAddressGone`. Transport errors have the request URL removed, since the URL holds the device token.

### Sealed

The sealed driver delivers a push without letting the gateway read it. It encrypts the notification to the device's public key and posts it to a [push gateway](/docs/subsystems/push-gateway), signing the request with an Ed25519 key. The Forge extension registers it. In a library setup, use `herald.WithDriver(&push.SealedDriver{})`.

| Key | Goes in | Required | Secret | Description |
|-----|---------|----------|--------|-------------|
| `signing_key` | Credential | Yes | Yes | Standard base64 of a 32-byte Ed25519 seed |
| `gateway_url` | Setting | Yes | No | The gateway's address. `https`, or `http` for `localhost`, `127.0.0.1` and `::1` only |

```go
driver := &push.SealedDriver{}
driver.Name()    // "sealed"
driver.Channel() // "push"
```

The device's `Address` is its gateway handle and its `PublicKey` is the key the notification is sealed to. A device with no 32-byte key fails with `push.ErrMissingPublicKey`, and an envelope over `push.MaxEnvelopeBytes` fails with `push.ErrPayloadTooLarge`. A gateway 410 comes back as `driver.ErrAddressGone`. Any other status is an error that carries the gateway's own message, cut to 200 bytes. [Push gateway](/docs/subsystems/push-gateway) has the headers, the statuses and the seal format.

### InApp

The InApp driver is a no-op pass-through. In-app notifications are handled directly by the Herald engine, which stores them in the inbox table after the driver returns success.

| Key | Goes in | Required | Secret | Description |
|-----|---------|----------|--------|-------------|
| *(none)* | -- | -- | -- | Nothing to configure |

```go
driver := &inapp.Driver{}
driver.Name()    // "inapp"
driver.Channel() // "inapp"
```

**How it works**: The `Send` method immediately returns `StatusDelivered`. The actual inbox entry is created by the Herald engine in the delivery pipeline after this driver returns. See [Inbox](/docs/subsystems/inbox) for details.

```go
func (d *Driver) Send(_ context.Context, _ *driver.OutboundMessage) (*driver.DeliveryResult, error) {
    return &driver.DeliveryResult{Status: message.StatusDelivered}, nil
}
```

## Registering Drivers

### With Forge Extension

When using the Forge extension, all built-in drivers are registered automatically:

```go
ext := extension.New()
// Registers: smtp, resend, twilio, fcm, sealed, inapp
```

### With Herald Directly

When using Herald directly (without Forge), register drivers using the `WithDriver` option:

```go
h, err := herald.New(
    herald.WithStore(myStore),
    herald.WithDriver(&email.SMTPDriver{}),
    herald.WithDriver(&email.ResendDriver{}),
    herald.WithDriver(&sms.TwilioDriver{}),
    herald.WithDriver(&push.FCMDriver{}),
    herald.WithDriver(&push.SealedDriver{}),
    herald.WithDriver(&inapp.Driver{}),
)
```

## Writing a Custom Driver

To add support for a new notification service, implement the `Driver` interface. The example below sketches an SES driver to show the shape. You don't need to write that one: Herald already ships it as the `github.com/xraph/herald/drivers/ses` module, registered with `&ses.Driver{}`.

```go
package ses

import (
    "context"
    "github.com/xraph/herald/driver"
    "github.com/xraph/herald/message"
)

type SESDriver struct{}

func (d *SESDriver) Name() string    { return "ses" }
func (d *SESDriver) Channel() string { return "email" }

// Fields says which keys the driver reads and where each one lives.
func (d *SESDriver) Fields() []driver.Field {
    return []driver.Field{
        {Key: "access_key_id", Label: "Access key ID", Required: true, Placement: driver.PlacementCredential},
        {Key: "secret_access_key", Label: "Secret access key", Required: true, Secret: true, Placement: driver.PlacementCredential},
        {Key: "region", Label: "Region", Required: true, Placement: driver.PlacementSetting},
    }
}

func (d *SESDriver) Validate(credentials, settings map[string]string) error {
    if credentials["access_key_id"] == "" {
        return fmt.Errorf("ses: missing required credential 'access_key_id'")
    }
    if credentials["secret_access_key"] == "" {
        return fmt.Errorf("ses: missing required credential 'secret_access_key'")
    }
    return nil
}

func (d *SESDriver) Send(ctx context.Context, msg *driver.OutboundMessage) (*driver.DeliveryResult, error) {
    accessKeyID := msg.Data["access_key_id"]
    secretKey := msg.Data["secret_access_key"]
    region := msg.Data["region"]

    // ... call AWS SES API ...

    return &driver.DeliveryResult{
        ProviderMessageID: sesMessageID,
        Status:            message.StatusSent,
    }, nil
}
```

If your driver calls an HTTP API, build its client with `driver.HTTPClient` instead of `&http.Client{}`. It behaves the same (default transport, your timeout, the transport's own errors) and records the call as a client span under the send, the way the built-in drivers do:

```go
client := driver.HTTPClient(10*time.Second, driver.Endpoint{
    Driver:      "ses",
    URLTemplate: "/v2/email/outbound-emails",
})
resp, err := client.Do(req)
```

`URLTemplate` names the span and is the only part of the path it records, so write any account ID, domain or device token in it as a placeholder (`/v3/{domain}/messages`). If the user supplies the whole URL, as with a webhook, leave `URLTemplate` empty and set `HideHost: true`, and the span carries no host either. The client sends no trace headers or baggage to the vendor. [Observability](/docs/subsystems/observability#vendor-calls) lists what the span holds.

Register the custom driver when creating your Herald instance:

```go
h, err := herald.New(
    herald.WithStore(myStore),
    herald.WithDriver(&ses.SESDriver{}),
    // ... other drivers
)
```

`Fields` is optional, but it's what Herald checks placement against. A driver without it still can't take `base_url` or `host` in `credentials`, yet Herald can't tell which of its other keys are settings, so it can't refuse those.

Then create a provider that uses the custom driver. The access keys go in `credentials` and the region goes in `settings`, matching the schema above:

```go
p := &provider.Provider{
    Name:    "Production SES",
    Channel: "email",
    Driver:  "ses",
    Credentials: map[string]string{
        "access_key_id":     "AKIA...",
        "secret_access_key": "secret...",
    },
    Settings: map[string]string{
        "region": "us-east-1",
    },
}
err := h.CreateProvider(ctx, p)
```
