---

Herald ships a [Forge](https://github.com/xraph/forge) extension that builds the store, runs migrations, registers the built-in drivers, mounts the REST API and provides `*herald.Herald` to the container. This guide covers setup in code and in YAML.

## Quick start

```go
package main

import (
    "log"

    "github.com/xraph/forge"
    heraldext "github.com/xraph/herald/extension"
    "github.com/xraph/herald/store/memory"
)

func main() {
    app := forge.NewApp(forge.AppConfig{
        Name: "notifications",
        Extensions: []forge.Extension{
            heraldext.New(
                heraldext.WithStore(memory.New()),
                heraldext.WithAPIMiddleware(requireAdmin), // your auth middleware
            ),
        },
    })

    if err := app.Run(); err != nil {
        log.Fatal(err)
    }
}
```

`requireAdmin` stands for your own `forge.Middleware`. `app.RegisterExtension(heraldext.New(...))` works too, as long as you call it before the app starts.

During `Register` the extension:

1. Loads configuration from YAML (or programmatic defaults).
2. Picks a store (see [store resolution](#store-resolution)).
3. Uses a `chronicle.Emitter` from the container for audit events if there is one, and slog if not.
4. Registers the built-in drivers (SMTP, Resend, Twilio, FCM, in-app) plus any you added with `WithDriver`.
5. Runs migrations, unless disabled.
6. Seeds the in-app provider and any `providers` from your config.
7. Mounts the REST API under `/herald`, unless disabled.
8. Provides `*herald.Herald` to the DI container.

## YAML configuration

Herald reads configuration from your Forge config under `extensions.herald`, falling back to a top-level `herald` key:

```yaml
extensions:
  herald:
    base_path: "/herald"
    grove_database: ""
    disable_routes: false
    disable_migrate: false
    credentials_key: "<base64 of 32 random bytes>"
    credentials_key_id: "2026-10"
    previous_credentials_keys:
      - id: "2026-01"
        key: "<base64>"
    dashboard_app_id: ""
    providers:
      - name: Resend
        app_id: myapp
        channel: email
        driver: resend
        credentials:
          api_key: re_xxx
        settings:
          from: hello@example.com
        priority: 0
```

### Config fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `base_path` | `string` | `"/herald"` | URL prefix for all Herald routes |
| `grove_database` | `string` | `""` | Named Grove DB to resolve from DI |
| `disable_routes` | `bool` | `false` | Skip automatic route registration |
| `disable_migrate` | `bool` | `false` | Skip automatic database migration |
| `credentials_key` | `string` | `""` | Base64 AES-256 key; with it set, new provider credentials are stored encrypted |
| `credentials_key_id` | `string` | `"k1"` | ID stored with each encrypted credential |
| `previous_credentials_keys` | list of `id`, `key` | none | Older keys Herald can still decrypt with |
| `providers` | list | none | Providers to create once, if no provider with that name exists for the app yet |
| `dashboard_app_id` | `string` | `""` | The app the dashboard shows to a session with no `app_id` claim |

The extension `Config` also embeds `herald.Config` (`DefaultLocale`, `MaxBatchSize`, `TruncateBodyAt`), but those fields carry no YAML tags, so `default_locale`, `max_batch_size` and `truncate_body_at` in a config file are ignored. See [engine settings](#engine-settings) for how to set them.

### Config resolution order

1. The YAML file (`extensions.herald`, then `herald`).
2. Programmatic options fill fields the file left empty, and `WithDisableRoutes` or `WithDisableMigrate` set in code still turn the feature off.
3. Defaults fill whatever is still zero.

## Programmatic options

| Option | Description |
|--------|-------------|
| `WithStore(s store.Store)` | Use this store, unless a grove database is found (see below) |
| `WithGroveDatabase(name string)` | Resolve a `*grove.DB` from DI; `""` means the default one |
| `WithBasePath(path string)` | Set the route URL prefix |
| `WithAPIMiddleware(mw ...forge.Middleware)` | Run your middleware in front of every REST route |
| `WithConfig(cfg Config)` | Replace the full config struct |
| `WithHeraldOption(opt herald.Option)` | Pass a raw `herald.Option` |
| `WithDriver(d driver.Driver)` | Register an extra driver |
| `WithDisableRoutes()` | Disable automatic route registration |
| `WithDisableMigrate()` | Disable automatic migration |
| `WithRequireConfig(bool)` | Fail `Register` when the config file has no Herald key |

### Engine settings

`WithHeraldOption(herald.WithDefaultLocale("fr"))` doesn't stick today. The extension fills `DefaultLocale` and `MaxBatchSize` from its own config defaults and appends them after your options, so the locale ends up `en`. Set them through `WithConfig` instead, starting from the defaults:

```go
cfg := heraldext.DefaultConfig()
cfg.DefaultLocale = "fr"

ext := heraldext.New(
    heraldext.WithConfig(cfg),
    heraldext.WithStore(memory.New()),
)
```

`WithConfig` replaces the whole config, so put it before the options that write into it. `TruncateBodyAt` is never passed to the engine, which always truncates logged bodies at 4096 characters. `MaxBatchSize` is stored but nothing reads it.

`WithHeraldOption` is still the way to pass options the config doesn't cover, such as `herald.WithLogger`.

## Store resolution

The extension builds its store from the first of these that applies:

1. `WithGroveDatabase(name)`, or a non-empty `grove_database`: the named (or default) `*grove.DB` from the container.
2. A default `*grove.DB` in the container, if the Grove extension registered one.
3. The store from `WithStore`.

The driver picks the backend:

```go
switch db.Driver().Name() {
case "pg":     return pgstore.New(db), nil
case "sqlite": return sqlitestore.New(db), nil
case "mongo":  return mongostore.New(db), nil
}
```

A grove store is passed to `herald.New` after the one from `WithStore`, so it wins. If you want `WithStore` in an app that also runs the Grove extension, don't register a default grove database. If none of these applies, `Register` fails with `ErrNoStore`.

## Built-in drivers

The extension always registers these:

| Driver | Package | Channel |
|--------|---------|---------|
| SMTP | `herald/driver/email` | `email` |
| Resend | `herald/driver/email` | `email` |
| Twilio | `herald/driver/sms` | `sms` |
| FCM | `herald/driver/push` | `push` |
| InApp | `herald/driver/inapp` | `inapp` |

Add the drivers in `github.com/xraph/herald/drivers/<name>` (SendGrid, Slack, APNs and the rest) with `WithDriver()`.

## Migration on startup

By default, the extension runs `store.Migrate(ctx)` during `Register`. It's idempotent, so running it on every start is safe. To manage migrations yourself:

```go
heraldext.New(
    heraldext.WithDisableMigrate(),
)
```

Or in YAML:

```yaml
extensions:
  herald:
    disable_migrate: true
```

## Route registration

The extension mounts the REST API under the base path plus `/v1`:

| Group | Base | Endpoints |
|-------|------|-----------|
| Providers | `/herald/v1/providers` | CRUD for providers, plus `POST /encrypt` |
| Templates | `/herald/v1/templates` | CRUD for templates and their `versions` |
| Send | `/herald/v1/send`, `/herald/v1/notify` | Send notifications |
| Messages | `/herald/v1/messages` | Query the delivery log |
| Inbox | `/herald/v1/inbox` | User in-app notifications |
| Preferences | `/herald/v1/preferences` | User notification preferences |
| Config | `/herald/v1/config` | Scoped routing configuration |

The API has no authentication of its own. Pass yours with `WithAPIMiddleware`; without it, the extension logs a warning at startup, because anyone who can reach the API can read and change notification data. The middleware is also where tenant isolation lives: it has to bind each caller to the `app_id` they may use.

To mount the routes yourself:

```go
ext := heraldext.New(
    heraldext.WithDisableRoutes(),
    heraldext.WithGroveDatabase(""),
)
app.RegisterExtension(ext)

// After the app has registered the extension:
group := app.Router().Group("/api/notifications")
group.Use(requireAdmin) // WithAPIMiddleware doesn't apply here
ext.RegisterRoutes(group)
```

## Health checks

`Health(ctx)` pings the store, and Forge includes it in its health endpoint.

## DI container integration

After registration, resolve the engine from the container:

```go
h, err := forge.Inject[*herald.Herald](app.Container())
if err != nil {
    log.Fatal("herald not registered: ", err)
}

result, err := h.Send(ctx, &herald.SendRequest{
    AppID:    "myapp",
    Channel:  "email",
    To:       []string{"user@example.com"},
    Template: "welcome",
    Data:     map[string]any{"name": "Alice"},
})
```

## Lifecycle

| Method | When called | What happens |
|--------|------------|-------------|
| `Register(app)` | App startup | Load config, build Herald, migrate, seed providers, register routes, provide to DI |
| `Start(ctx)` | After all extensions registered | Marks the extension started; the engine has nothing to start |
| `Health(ctx)` | Health check requests | Pings the store |
| `Stop(ctx)` | Graceful shutdown | Marks the extension stopped |
