Herald can run standalone or as a Forge extension. Both modes share the same core `Config` struct, with the extension adding route and migration options on top.

## herald.Config

**Import:** `github.com/xraph/herald`

The root `Config` struct controls core notification delivery behavior:

```go
type Config struct {
    // DefaultLocale is the default locale for template rendering (default: "en").
    DefaultLocale string

    // MaxBatchSize is the maximum number of notifications per batch send.
    MaxBatchSize int

    // TruncateBodyAt is the maximum message body length stored in the delivery log.
    // Bodies longer than this are truncated. 0 means no truncation.
    TruncateBodyAt int
}
```

### Field reference

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `DefaultLocale` | `string` | `"en"` | BCP 47 locale tag used when a `SendRequest` does not specify a locale. |
| `MaxBatchSize` | `int` | `100` | Maximum recipients per batch send via `Herald.Notify`. |
| `TruncateBodyAt` | `int` | `4096` | Maximum character length for the `Body` field in delivery log messages. Set to `0` to disable truncation. |

### DefaultConfig

`DefaultConfig()` returns a `Config` with sensible defaults:

```go
cfg := herald.DefaultConfig()
// cfg.DefaultLocale  = "en"
// cfg.MaxBatchSize   = 100
// cfg.TruncateBodyAt = 4096
```

## Option functions

Herald uses the functional options pattern. `Option` is a function type that configures a `Herald` instance:

```go
type Option func(*Herald) error
```

Options are passed to the `herald.New` constructor:

```go
h, err := herald.New(
    herald.WithStore(myStore),
    herald.WithDefaultLocale("fr"),
    herald.WithMaxBatchSize(50),
    herald.WithDriver(&email.SMTPDriver{}),
    herald.WithLogger(slog.Default()),
)
```

### Available options

| Option | Description |
|--------|-------------|
| `WithStore(s store.Store)` | Sets the persistence backend. **Required**: Herald returns `ErrNoStore` without it. |
| `WithLogger(l *slog.Logger)` | Sets the structured logger. Defaults to `slog.Default()`. |
| `WithDriver(d driver.Driver)` | Registers a notification driver (SMTP, Twilio, FCM, etc.). Can be called multiple times. |
| `WithDefaultLocale(locale string)` | Overrides the default locale for template rendering. |
| `WithMaxBatchSize(n int)` | Overrides the maximum batch size. |
| `WithCredentialKey(keyID string, key []byte)` | Encrypts provider credentials at rest with a 32-byte AES-256 key. `keyID` is stored beside every value it encrypts. See [Provider credentials](#provider-credentials). |
| `WithPreviousCredentialKey(keyID string, key []byte)` | Adds an old key that only decrypts, for rotation. Needs a current key too. |

### Minimal standalone setup

```go
import (
    "log/slog"

    "github.com/xraph/herald"
    "github.com/xraph/herald/driver/email"
    "github.com/xraph/herald/store/memory"
)

h, err := herald.New(
    herald.WithStore(memory.New()),
    herald.WithDriver(&email.SMTPDriver{}),
)
if err != nil {
    log.Fatal(err)
}
```

## Extension configuration

**Import:** `github.com/xraph/herald/extension`

When running as a Forge extension, Herald wraps the core config with additional fields for route registration, migration control, and Grove database integration.

### extension.Config

```go
type Config struct {
    herald.Config `json:",inline" yaml:",inline" mapstructure:",squash"`

    // BasePath is the URL prefix for all herald routes (default: "/herald").
    BasePath string `json:"base_path" yaml:"base_path" mapstructure:"base_path"`

    // DisableRoutes disables automatic route registration with the Forge router.
    DisableRoutes bool `json:"disable_routes" yaml:"disable_routes" mapstructure:"disable_routes"`

    // DisableMigrate disables automatic database migration on Register.
    DisableMigrate bool `json:"disable_migrate" yaml:"disable_migrate" mapstructure:"disable_migrate"`

    // GroveDatabase is the name of a grove.DB registered in the DI container.
    GroveDatabase string `json:"grove_database" yaml:"grove_database" mapstructure:"grove_database"`

    // DashboardAppID is the app the dashboard manages when the session has
    // no app_id claim.
    DashboardAppID string `json:"dashboard_app_id" yaml:"dashboard_app_id" mapstructure:"dashboard_app_id"`
}
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `BasePath` | `string` | `"/herald"` | URL prefix for all Herald API routes. |
| `DisableRoutes` | `bool` | `false` | When `true`, the extension does not register routes automatically. |
| `DisableMigrate` | `bool` | `false` | When `true`, the extension skips automatic schema migration. |
| `GroveDatabase` | `string` | `""` | Name of the Grove database in the DI container. Empty uses the default unnamed DB. |
| `DashboardAppID` | `string` | `""` | `dashboard_app_id`: the app the dashboard manages when a session carries no `app_id` claim. A claim always wins. |
| `CredentialsKey` | `string` | `""` | `credentials_key`: 32 bytes, standard base64. Encrypts provider credentials at rest. Supports `${ENV}` interpolation. |
| `CredentialsKeyID` | `string` | `"k1"` | `credentials_key_id`: stored beside every value the key encrypts. Change it when you rotate. |
| `PreviousCredentialsKeys` | `[]CredentialKeyConfig` | none | `previous_credentials_keys`: a list of `{id, key}`. They only decrypt, so values written under an older key keep working. |

### Extension options

```go
ext := extension.New(
    extension.WithGroveDatabase("primary"),
    extension.WithBasePath("/notifications"),
    extension.WithDisableRoutes(),
    extension.WithDisableMigrate(),
    extension.WithDriver(&sms.TwilioDriver{}),
)
```

| ExtOption | Description |
|-----------|-------------|
| `WithStore(s store.Store)` | Sets the persistence backend directly (bypasses Grove auto-detection). |
| `WithBasePath(path string)` | Sets the URL prefix for Herald API routes. |
| `WithConfig(cfg Config)` | Sets the full extension configuration. |
| `WithHeraldOption(opt herald.Option)` | Passes a raw `herald.Option` through to the core engine. |
| `WithDriver(d driver.Driver)` | Registers a notification driver. |
| `WithDisableRoutes()` | Disables automatic route registration. |
| `WithDisableMigrate()` | Disables automatic schema migration. |
| `WithRequireConfig(bool)` | Requires config to be present in YAML files (errors if missing). |
| `WithGroveDatabase(name string)` | Sets the Grove database name for auto-detection of the store backend. |
| `WithAPIMiddleware(mw ...forge.Middleware)` | Runs your middleware in front of every Herald REST route. See [Protecting the REST API](#protecting-the-rest-api). |

### YAML configuration

The extension loads configuration from Forge YAML config files. It checks two keys in order:

1. `extensions.herald` (namespaced, preferred)
2. `herald` (legacy)

```yaml
# config.yaml
extensions:
  herald:
    default_locale: "en"
    max_batch_size: 100
    truncate_body_at: 4096
    base_path: "/herald"
    disable_routes: false
    disable_migrate: false
    grove_database: "primary"
    credentials_key: "${HERALD_CREDENTIALS_KEY}"
    credentials_key_id: "2026-09"
    previous_credentials_keys:
      - id: "k1"
        key: "${HERALD_OLD_CREDENTIALS_KEY}"
```

YAML configuration takes precedence over programmatic defaults. Programmatic boolean flags (`DisableRoutes`, `DisableMigrate`) override YAML when set to `true`.

### Grove auto-detection

When `GroveDatabase` is set (via YAML or `WithGroveDatabase`), the extension resolves a `*grove.DB` from the Forge DI container and auto-constructs the appropriate store backend based on the Grove driver type:

| Grove driver | Store backend |
|--------------|---------------|
| `pg` | `store/postgres.Store` |
| `sqlite` | `store/sqlite.Store` |
| `mongo` | `store/mongo.Store` |

```go
// The extension does this internally:
switch db.Driver().Name() {
case "pg":
    return pgstore.New(db), nil
case "sqlite":
    return sqlitestore.New(db), nil
case "mongo":
    return mongostore.New(db), nil
}
```

### Protecting the REST API

Herald doesn't know your auth scheme, so it doesn't authenticate anything on its own. You put your auth in front of its routes with `WithAPIMiddleware`:

```go
ext := extension.New(
    extension.WithAPIMiddleware(requireStaff, bindAppID),
)
```

The middleware runs on every route Herald mounts. Without it, startup logs a warning that the API is unauthenticated.

Tenant isolation rests on the same middleware. Herald takes `app_id` from the request as given, so your middleware has to bind each caller to the app they're allowed to use. Herald then answers 404 for any row outside that app.

If you turn Herald's routes off (`WithDisableRoutes`) and mount them yourself through `ext.RegisterRoutes(router)`, none of this middleware runs. Put your own on that router with `router.Use` before you call `RegisterRoutes`, or every route is open.

### Built-in drivers

The Forge extension automatically registers all built-in drivers during `Init`:

- `email.SMTPDriver`: SMTP email delivery
- `email.ResendDriver`: Resend API email delivery
- `sms.TwilioDriver`: Twilio SMS delivery
- `push.FCMDriver`: Firebase Cloud Messaging push notifications
- `inapp.Driver`: In-app inbox notifications

You only need to call `WithDriver` for custom or third-party drivers.

## Provider credentials

Set `credentials_key` and Herald encrypts provider credentials before it stores them. You need 32 random bytes, base64 encoded:

```bash
openssl rand -base64 32
```

Each value is encrypted on its own with AES-256-GCM and carries the ID of the key that encrypted it (`credentials_key_id`, `k1` by default). Herald decrypts them in memory only to send, or to validate an update, and the REST API never returns them. You see which keys a provider has and whether each is encrypted, never the values.

At startup the extension tells you which mode you're in. With a key it logs an Info line naming the key ID. Without one it logs a warning:

```
herald: provider credentials are stored in plaintext; set credentials_key to encrypt them
```

It never logs key material.

### Encrypting rows you already have

Turning the key on doesn't touch what's already stored. Run `EncryptStoredCredentials` once for each app after you set it:

```go
rep, err := h.EncryptStoredCredentials(ctx, "myapp")
// rep.Providers, rep.ValuesEncrypted, rep.AlreadyEncrypted
```

Over REST that's `POST /herald/v1/providers/encrypt?app_id=myapp`. A second run changes nothing, so it's safe to repeat. Without a key configured it fails with `ErrNoCredentialKey`.

### Rotating the key

Put the new key in `credentials_key` with a new `credentials_key_id`, and move the old one into `previous_credentials_keys` under its old ID. New writes use the new key, and values written under the old one still decrypt. A provider whose credentials were encrypted under a key you've removed entirely can't be sent through or updated: `UpdateProvider` refuses with `ErrCredentialKeyUnavailable`, names the missing key ID and leaves the stored row alone.

## Accessing the Herald instance

After extension registration, the `*herald.Herald` instance is available from the Forge DI container:

```go
import "github.com/xraph/vessel"

h, err := vessel.Inject[*herald.Herald](app.Container())
```

Or directly from the extension:

```go
ext.Herald() // *herald.Herald (nil until Register is called)
ext.API()    // *api.ForgeAPI
ext.Config() // herald.Config
```
